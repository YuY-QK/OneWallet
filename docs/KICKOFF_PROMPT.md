# 启动指令

把下面"通用指令"整段发给执行的 AI 即可开始。需要指定范围时，把最后一行换成"可选的范围指定"中的一句。

## 通用指令

```
你要接手开发 OneWallet：一个本地优先的个人加密资产看板加离线密钥保险库，用 Flutter 开发。
它只查看资产和保管密钥，不做任何签名、转账、交易。

仓库：https://github.com/YuY-QK/OneWallet （在默认分支上工作）

产品、架构、安全方案和任务清单都已定稿并写在仓库里。你的工作是严格按文档实现，不是重新设计。

开始前，按顺序读完这些文件：
1. AGENTS.md
2. docs/EXECUTION_GUIDE.md（执行手册，规定了工作流程、完成标准、禁止事项、何时必须停下来问我）
3. docs/progress.md
4. docs/TASKS.md
5. docs/DEV_GUIDELINES_v1.0.md（第 1 节"安全红线"必须逐条读完）
6. docs/IMPLEMENTATION_SPEC_v1.0.md
然后读你要做的任务里"依据"指向的章节。

环境：Flutter 3.47.9。先运行 flutter pub get 和 tools/check.sh，确认基线全部通过；不通过就先告诉我，不要开工。

工作方式：
- 按 docs/EXECUTION_GUIDE.md 第 4 节的流程，一次只做一个任务。
- 每个任务从默认分支建分支 feat/<任务编号>-<简述>，完成后推送该分支。
- 先写测试再写实现；tools/check.sh 必须全部通过。
- 完成后更新 docs/TASKS.md 中的任务状态，并按执行手册第 8 节的格式向我汇报。
- 带〔设备〕〔真机〕〔用户〕标签而你无法验收的部分，把代码和自动化测试做完，状态标为受阻并写明验收步骤。不要把没验证的东西说成已验证。

硬性约束（违反任何一条都不可接受）：
- 不写任何能动用资金的代码：签名、转账、下单、划转、提现。
- 不自己实现密码学算法；不更换已选定的技术栈和库。
- 助记词、私钥、密码、API Secret 不得进入日志、异常信息、路由参数、状态对象、剪贴板、测试数据。
- 测试只用公开的 BIP39 测试向量，不使用任何真实的助记词或 API Key；不要让我把这些发给你。
- 不做文档范围之外的功能；不改包的划分、依赖方向和 docs/IMPLEMENTATION_SPEC_v1.0.md 中约定的名字，确需改动时先停下来问我。
- 不为了通过检查而删除测试、放宽规则或加忽略注释。

遇到 docs/EXECUTION_GUIDE.md 第 7 节列出的情况，停下来问我，同时给出你的建议。

现在开始：从 docs/TASKS.md 中按顺序取第一个未开始、依赖已满足、你的环境能完成的任务，先告诉我你选了哪个任务和你的实现计划（要点即可），然后直接开始做，不用等我确认。
```

## 可选的范围指定

把通用指令的最后一段换成下面某一句：

- **指定任务**：`现在开始：做任务 M0-09。先告诉我你的实现计划（要点即可），然后直接开始做。`
- **指定工作线**（多个 AI 并行时，每个 AI 一条线，见 TASKS.md 末尾的表）：`现在开始：你负责工作线 C（链上数据），按该线的顺序逐个完成任务，只修改该线的目录和共用文件中属于你的条目。`
- **连续执行**：`现在开始：按顺序连续完成 M0-07、M0-08、M0-09 和 M1 的全部〔离线〕任务，每完成一个汇报一次，然后继续下一个；遇到必须问我的情况再停。`
- **只做评审**：`现在不要写代码：通读全部文档和现有代码，列出你发现的矛盾、遗漏和风险，按严重程度排序。`

## 建议的分配方式

1. 第一个 AI 先单独完成 M0-09（领域模型与接口）。它是几乎所有任务的前置，并行会冲突。
2. 之后可以同时开三到四个 AI：工作线 A（界面基础）、B（领域与数据）、C（链上数据）、D（价格与映射）。
3. 工作线 F（平台与真机）需要你本人配合真机操作，建议用能连接你电脑的 AI 来做。
4. 每个分支合并前，可以再开一个 AI 用"只做评审"的方式检查它是否偏离文档。
