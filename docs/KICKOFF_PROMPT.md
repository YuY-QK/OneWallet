# 启动指令

把下面"通用指令"整段发给接手的 AI 即可开始。需要指定范围时，把最后一段换成"可选的范围指定"中的一句。

## 通用指令

```
你要接手开发 OneWallet：一个本地优先的个人加密资产看板加离线密钥保险库，用 Flutter 开发。
它只查看资产和保管密钥，不做任何签名、转账、交易。

仓库：https://github.com/YuY-QK/OneWallet （在默认分支上工作）

项目已经做了一部分：文档全部定稿，工程骨架、数据层、各链与三家交易所的只读适配器、核心循环的页面、保险库核心与加密备份的格式都已完成并合并。
你的工作是接着做剩下的任务，严格按文档和已有代码的做法实现，不是重新设计，也不是重构已有的东西。

开始前，按顺序读完这些文件：
1. AGENTS.md
2. docs/HANDOFF.md（交接说明：现状、必须照做的做法与范本文件、剩余任务的分批顺序和每个任务的注意点。这是最重要的一份）
3. docs/EXECUTION_GUIDE.md（工作流程、完成标准、禁止事项、何时必须停下来问我）
4. docs/TASKS.md（任务清单，以它的状态为准）
5. docs/DEV_GUIDELINES_v1.0.md（第 1 节"安全红线"必须逐条读完）
6. docs/IMPLEMENTATION_SPEC_v1.0.md
然后读你要做的任务里"依据"指向的章节，以及 docs/HANDOFF.md 第 2.1 节为这类任务指定的范本文件。范本文件必须先读再动手。
涉及保险库、应用锁、加密备份的任务，另须通读 docs/SECURITY_DESIGN_v1.0.md 全文。
想知道应用现在长什么样，看 docs/screenshots/；设计目标看 docs/prototype.html。

环境：Flutter 3.47.9。先运行 flutter pub get 和 tools/check.sh，确认基线输出"全部通过"；不通过就先告诉我，不要开工。
（flutter pub get 会从 GitHub Releases 下载 SQLCipher 预编译库，网络不通会失败；测试输出里的 "ERROR CORE sqlcipher…" 是预期输出。）

工作方式：
- 按 docs/HANDOFF.md 第 3 节的批次顺序做，同一批做完再做下一批。一次只做一个任务。
- 每个任务从默认分支建分支 feat/<任务编号>-<简述>，完成后推送该分支，不要直接改默认分支。
- 新代码照范本文件的结构、命名、测试写法来写，与已有代码保持一致。
- 先写测试再写实现；tools/check.sh 必须输出"全部通过"。
- 开工前和交付前各同步一次默认分支（git fetch 后把 origin/main 合并进你的分支），再跑 tools/check.sh。默认分支上别人会新增错误类型等内容，不同步的话你的分支合并时会编译失败。
- 每做完一批页面，把新页面加进截图测试并重新生成截图，对照 docs/prototype.html 检查。生成截图的机器必须有中文字体；提交前打开几张图确认中文不是方块、界面与原型一致。
- 完成后更新 docs/TASKS.md 中的任务状态，按执行手册第 8 节的格式向我汇报。汇报里必须单列：你自行决定的事项、没能核对或没能验证的事项、你认为文档或已有代码有问题的地方。

关于真机：这个项目的真机验收统一放在最后由我来做。带〔设备〕〔真机〕标签的任务，你把代码和自动化测试做完，把没在真机上验证的项目追加到 docs/DEVICE_TEST_CHECKLIST.md。原生代码没编译过的要单独标"未编译"。纯真机验收的任务（docs/HANDOFF.md 第 3 节末尾列出的那些）不用你做。不要把没验证的东西说成已验证。

预留给别人、你不要做的任务（在 docs/TASKS.md 中标为 [~]）：应用锁核心（M3-01）、保险库与加密备份的用例层（M4-00）、硬件密钥（M0-11）。也不要改动 packages/ow_vault。
依赖它们的页面任务，要等对应条目变成 [x] 才能开始：M3-02 等 M3-01；M4-05 至 M4-09、M5-03、M5-04、M5-05 等 M4-00。开工前看一眼 docs/TASKS.md 的最新状态。

你现在可以做的任务（按这个顺序；标了 [x] 的跳过）：
1. M2-04 四类链的接线
2. M1-15 目录接入页面
3. M2-10 添加交易所账户（P06）与凭据存储 —— 涉及 API 密钥的保存，做完我会找人专门审一遍
4. M2-11 交易所账户详情（P08）、M2-12 币种详情（P09）、M2-13 同步状态（P21）
5. M3-03 账户列表完整版、M3-04 地址簿
6. M3-05 每日快照与净值曲线、M3-06 备份清单
7. M3-07 设置与关于页、M3-08 设备完整性提示
8. M4-04 防截屏与安全输入
9. M1-13 集成测试
M2-09（Bitget）需要我先提供文档来源，没有我的通知不要做。
每个任务的注意点在 docs/HANDOFF.md 第 3 节对应的表格里，开工前先读那一行。

硬性约束（违反任何一条都不可接受）：
- 不写任何能动用资金的代码：签名、转账、下单、划转、提现、兑换、借贷、申购赎回。交易所只调用查询类接口。
- 不自己实现密码学算法；不更换已选定的技术栈和库；不改保险库与备份文件的格式、密钥层级、算法。
- 助记词、私钥、密码、API Secret 不得进入日志、异常信息、路由参数、状态对象、剪贴板、测试数据。
- 测试只用公开的 BIP39 测试向量，不使用任何真实的助记词或 API Key；不要让我把这些发给你。
- 金额只用 Decimal，不用浮点数。
- 外部接口先读官方文档、把核对结果写进 docs/EXTERNAL_APIS.md 再写代码。读不到文档就停下来告诉我，不要凭印象写接口路径。
- 不做文档范围之外的功能；不重构已有代码；不改包的划分、依赖方向和 docs/IMPLEMENTATION_SPEC_v1.0.md 中约定的名字。确需改动时先停下来问我。
- 不为了通过检查而删除或跳过测试、放宽 tools/ci/check_deps.dart 的规则、加忽略注释，也不要把断言改弱去迁就错误的行为。

遇到 docs/EXECUTION_GUIDE.md 第 7 节列出的情况，停下来问我，同时给出你的建议。

现在开始：读完上面的文件后，先用几句话告诉我你对现状的理解，然后从上面"你现在可以做的任务"的第 1 项做起，每完成一个任务汇报一次再继续下一个；遇到必须问我的情况再停。
```

## 可选的范围指定

把通用指令的最后一段换成下面某一句：

- **指定任务**：`现在开始：做任务 M2-10。先告诉我你的实现要点，然后直接开始做。`
- **指定批次**：`现在开始：做 docs/HANDOFF.md 第 3 节的第一批，按表里的顺序逐个完成，每完成一个汇报一次再继续；遇到必须问我的情况再停。`
- **由它当协调者**（它能派子任务给其他模型时）：`现在开始：你做协调者。按 docs/HANDOFF.md 第 3 节的批次和建议档位，把任务派给合适的模型，同时进行的不超过 2 到 3 个；每个交回的任务按第 4 节的审查清单审查，通过后再合并；每合并一个任务向我汇报一次。你自己不写大段实现代码。`
- **只做评审**：`现在不要写代码：通读文档和已有代码，对照 docs/DEV_GUIDELINES_v1.0.md 第 1 节的红线，列出你发现的矛盾、遗漏和风险，按严重程度排序。`

## 建议的分配

1. 第一批和第二批互相影响小，可以各交给一个 AI 同时做；之后的批次按顺序。
2. 第四批（保险库）建议用你手上最强的模型，并在它做完核心三项（M4-01 至 M4-03）后，另开一个 AI 用"只做评审"的方式审一遍，再继续做页面。
3. 每个分支合并前，对照 `docs/HANDOFF.md` 第 4 节的审查清单过一遍。
4. 需要你本人配合的事：Bitget 的文档来源（M2-09）、应用图标（M6-05）、最后的真机整体测试。
