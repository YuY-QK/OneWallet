# OneWallet 开发计划

> 版本 v1.0 · 2026-11-10 · 状态：待确认
> 不给出日历日期；里程碑按顺序推进，每个里程碑达到完成标准后再进入下一个。

## 1. 计划目标与边界

**交付目标**：PRD v1.0 的全部内容，在 iOS 和 Android 真机上自用。

**明确不纳入**：桌面端与平板的发布（只保证架构可扩展）；应用商店上架；第三方审计；PRD"后续候选"中的各项。

## 2. 里程碑总览

| 里程碑 | 主题 | 用户可见的结果 |
|---|---|---|
| M0 | 工程基础与技术验证 | 空壳 app 可运行；三项关键风险有结论 |
| M1 | 核心循环 | 添加一个 EVM 地址，在总览看到资产 |
| M2 | 全部数据源 | 四类链加四家交易所全部接入，总额可信 |
| M3 | 管理与备份清单 | 应用锁、地址簿、备份清单、净值曲线、设置 |
| M4 | 保险库 | 助记词与私钥入库、查看、派生地址 |
| M5 | 加密备份 | 导出、恢复、独立解密工具 |
| M6 | 稳定化与自用发布 | 安全自查通过，装到日常手机 |

## 3. 分阶段任务

### M0 工程基础与技术验证

| 任务 | 产出 | 完成标准 |
|---|---|---|
| 建立工作区与各包骨架 | TECH_DESIGN 3.3 的目录结构 | `flutter run` 在 iOS 与 Android 上启动空壳 |
| 配置静态检查、格式化、CI | `analysis_options.yaml`、CI 流程 | 提交触发格式、检查、测试 |
| 依赖边界检查脚本 | `tools/ci/check_deps.dart` | 故意违规时 CI 失败 |
| 响应式外壳 | `AdaptiveScaffold`、`ListDetailLayout`、四个 Tab 的空页面 | 窄屏显示底部 Tab；拉宽窗口切换为侧栏 |
| 主题与基础组件 | 按选定的视觉方向 | 浅色与深色可切换 |
| **验证一：地址派生** | 候选库对比报告；选定方案；测试向量用例 | 全部官方测试向量通过；与三款主流钱包的地址一致 |
| **验证二：硬件密钥插件** | iOS 与 Android 的最小插件 | 真机上完成包裹、解包；指纹变更后失效 |
| **验证三：Argon2id 定标** | 各参数在真机上的耗时表 | 选定参数，解锁耗时在 1 至 2 秒 |
| 数据库与安全存储打通 | SQLCipher 加 Drift 可读写；密钥存取 | 沙盒中导出的数据库文件无法直接打开 |

## 5. 依赖与门禁

- M0 的三项验证全部有结论后才能进入 M1；任何一项不达标，先调整方案并更新 TECH_DESIGN。
- M4 依赖 M0 的验证一、二、三，以及 M3 的应用锁。
- M5 依赖 M4。
- M1 至 M3 与保险库无关，不存任何密钥，可以先行自用。
- 在 M6 的安全自查全部通过之前，保险库里只放测试钱包的密钥，不放主力钱包的。

## 6. 测试与质量门禁

每个里程碑结束时：

- 格式、静态检查、全部自动化测试通过。
- 覆盖率达到 TECH_DESIGN 第 8 节的门槛。
- 依赖边界检查通过。
- 该里程碑涉及的 PRD 验收条目在真机上通过。
- `docs/progress.md` 已更新。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 没有合适的派生库（维护差或不支持桌面） | M4 受阻 | M0 即验证；备选是经 FFI 调用成熟的原生库 |
| 免费数据服务额度不够 | 同步慢或失败 | 加长缓存、降低并发；允许切换服务商；必要时用付费档 |
| 交易所接口变更或地区限制 | 某家不可用 | 适配器相互独立；失败只影响该账户 |
| 交易所理财类产品余额取不全 | 总额偏低 | 逐家核对；取不到的在 P08 明示"未包含" |
| 两个平台硬件密钥行为差异大 | 保险库体验不一致 | 统一由接口屏蔽；差异写入 SECURITY_DESIGN |
| 范围膨胀 | 迟迟不能自用 | 严格按 PRD 第 5 节；新想法进"后续候选" |
| 保险库存在未发现的缺陷 | 资产风险 | 第 5 节的门禁；始终保留纸质备份；对外发布前必须审计 |
