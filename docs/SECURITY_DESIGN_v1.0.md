# 《OneWallet》安全设计文档

> 版本 v1.0 · 2026-11-10 · 状态：已确认（2026-11-10）
> 本文是保险库、应用锁和加密备份的权威说明。任何涉及密钥的代码改动，先改本文。

## 1. 要保护什么

| 资产 | 泄露后果 | 等级 |
|---|---|---|
| 助记词、私钥 | 对应钱包资产被全部转走，不可逆 | 最高 |
| 主密码、备份密码 | 配合保险库文件或备份文件可解出全部密钥 | 最高 |
| 交易所 API Secret（只读） | 余额与交易记录被窥视；若用户误开了交易权限则可被恶意交易 | 高 |
| 地址、余额、账户关系 | 隐私泄露，可能成为针对性攻击的目标 | 中 |
| PIN | 可进入 app 看到看板数据；不能单独解开保险库 | 中 |

## 2. 威胁模型

| 编号 | 威胁 | 应对 | 残余风险 |
|---|---|---|---|
| A1 | 手机丢失或被盗（已锁屏） | 系统级加密；数据库加密；保险库密钥由硬件密钥和主密码保护 | 极低 |
| A2 | 他人拿到已解锁的手机 | 应用锁；查看明文每次都要验证 | 生物识别被胁迫使用 |
| A3 | 保险库文件或备份文件被拷走 | Argon2id 加 XChaCha20-Poly1305；强度取决于密码 | 弱密码可被离线暴力破解 |
| A4 | 同设备上的恶意 app | 系统沙盒；不使用剪贴板；Android 禁止截屏；敏感数据不放外部存储 | 已越狱或 root 的设备上沙盒失效 |
| A5 | 恶意输入法记录输入 | iOS 上敏感输入框使用系统安全输入（禁用第三方键盘）；助记词输入提供应用内词表键盘 | Android 上私钥输入仍经过系统输入法（见 6.3） |
| A6 | 录屏、投屏、截屏 | Android 设置禁止截屏标志；iOS 检测录屏时隐藏内容 | iOS 无法阻止单张截屏；无法防止他人偷看或拍摄屏幕 |
| A7 | 依赖包被投毒 | 保险库包依赖白名单；锁定版本；保险库包无网络能力；升级依赖须审阅差异 | 被投毒的界面层依赖仍可能在明文显示时读取（见 6.5） |
| A8 | 自己代码的缺陷（日志泄露、加密误用） | 只用成熟库的高层接口；日志脱敏；静态检查；测试向量；本文第 8 节清单 | 未经第三方审计 |
| A9 | 网络中间人 | 仅 HTTPS；保险库不联网 | 低 |
| A10 | 数据服务商得知地址与 IP 的对应关系 | 在 P20 明示；允许自定义 RPC | 隐私上的固有代价 |
| A11 | 系统云备份把数据带出设备 | 数据库与保险库排除出系统备份；安全存储条目设为仅本设备 | 低 |
| A12 | 用户忘记主密码 | 创建时强制确认；生物识别仍可用时可抄录后重建 | 两者都失效则无法恢复——这是设计使然 |
| A13 | 设备损坏且没有导出备份 | 备份清单持续提醒；鼓励保留纸质备份 | 用户不导出则无解 |
| A14 | 仿冒的假 app | 第一版仅自用，不公开分发 | 对外发布时须重新评估 |

**不在防护范围内**：已被完全控制的设备（系统级木马、已 root 且被植入恶意软件）；对用户本人的胁迫；硬件级攻击。

## 3. 密钥层级

```
主密码 ──Argon2id(salt, 参数)──► KEK_pw ──┐
                                          ├─► 解开 ► VMK（保险库主密钥，32 字节随机数）
硬件密钥（需生物识别）─────────────────────┘            │
                                                      ├─ KDF("ow_items") ► K_item  加密每个密钥条目
                                                      └─ KDF("ow_fprnt") ► K_fp    计算查重指纹
```

- **VMK**：创建保险库时由系统安全随机数生成，永不以明文落盘。
- **两份包裹**：同一个 VMK 被包裹两次，任一份都能解开。
  - **密码包裹**：`KEK_pw = Argon2id(主密码, 16 字节随机 salt)`，用 XChaCha20-Poly1305 加密 VMK，结果存入保险库文件头。可随备份迁移到其他设备。
  - **硬件包裹**：由平台硬件密钥保护，绑定本设备与当前已登记的生物识别。不可迁移。
- **子密钥**：用 libsodium 的密钥派生函数从 VMK 派生，不同用途使用不同的上下文标签。

## 4. 算法与参数

| 用途 | 算法 | 参数 |
|---|---|---|
| 密码派生 | Argon2id | 保险库：内存不低于 64 MiB，迭代 3，并行 1；备份文件：目标 256 MiB，迭代 3。M0 在真机上定标，参数写入文件头 |
| 对称加密 | XChaCha20-Poly1305（IETF） | 256 位密钥，24 字节随机 nonce |
| 子密钥派生 | libsodium `crypto_kdf` | 8 字节上下文标签 |
| 查重指纹 | 带密钥的 BLAKE2b（`crypto_generichash`） | 输出截取 16 字节 |
| 随机数 | libsodium `randombytes_buf` | — |
| PIN 校验 | Argon2id | 结果存系统安全存储；见第 7 节 |
| 数据库 | SQLCipher 默认配置（AES-256） | 256 位随机密钥 |

规则：
- 只调用库的高层接口，不自己拼装加密模式。
- 每次加密都生成新的随机 nonce，不复用、不计数。
- 所有密文都带关联数据（AAD）：格式版本号、条目 id、条目类型，防止密文被调换。
- 比较密钥材料和校验值时使用常量时间比较。

## 5. 存储格式

### 5.1 保险库文件 `vault.owv`

```
{
  "format": "onewallet-vault",
  "version": 1,
  "kdf": { "alg": "argon2id", "salt": b64, "mem_kib": 65536, "iters": 3, "parallelism": 1 },
  "wrapped_vmk_pw": { "nonce": b64, "ct": b64 },
  "items": [
    { "id": "uuid", "kind": "mnemonic|private_key", "nonce": b64, "ct": b64 }
  ]
}
```

- 条目明文是一段 JSON：助记词、可选 passphrase、或私钥与链类型。
- 硬件包裹的 VMK 不在此文件内，由平台层保存（见 6.1）。
- 写入采用"写临时文件、落盘、原子重命名"，并保留上一版本作为 `.bak`，写入失败不破坏原文件。
- 条目名称、关联账户等元数据在主数据库中；保险库文件不含这些，也不含地址。

### 5.2 加密备份文件 `.owbak`

```
魔数 "OWBK" | 版本(1 字节) | 头部长度(4 字节) | 头部 JSON | 密文
头部 JSON：{ "kdf": {...同上，参数更强...}, "nonce": b64, "created_at": "...", "app_version": "..." }
密文 = XChaCha20-Poly1305( Argon2id(备份密码), nonce, gzip(载荷 JSON), AAD = 魔数‖版本‖头部 JSON )
```

- 载荷包含：账户、地址、备份状态、设置、全部密钥条目的明文、可选的交易所凭据。
- 备份文件自成一体：只需备份密码即可解密，不依赖任何设备或硬件密钥。
- 格式说明随仓库公开（`tools/backup_decrypt/FORMAT.md`），并提供独立解密工具。工具必须能在断网环境运行，且只依赖广泛可得的密码学库。
- 版本升级时旧版本必须保持可读。

## 6. 平台实现

### 6.1 硬件包裹（`HardwareKeyStore`）

| 平台 | 实现 | 要点 |
|---|---|---|
| iOS | 把 VMK 存为钥匙串条目，访问控制设为"需要当前已登记的生物识别"，可访问性设为"设备已设密码时、仅本设备" | 读取时系统弹出面容或指纹验证；生物识别变更后条目失效；不进入 iCloud 钥匙串 |
| Android | 在系统 Keystore 中生成 AES-256-GCM 密钥：需要用户验证、生物识别变更即失效；有独立安全芯片（StrongBox）时优先使用。用它加密 VMK，密文存应用私有目录 | 解密必须经由绑定了该密钥的生物识别弹窗 |
| 桌面端（后续） | macOS 用钥匙串加 Touch ID；Windows 用 Hello 与 TPM；Linux 多数情况没有 | 没有硬件支持时，`PlatformCapabilities.hardwareKeystore` 为假，保险库只能用主密码解锁 |

硬件包裹失效（生物识别变更、系统重置）时：要求输入主密码，验证成功后重新生成硬件包裹（PRD R30）。

### 6.2 应用安全存储（`SecretStore`）

存放数据库密钥、API Key 与 Secret、数据源 Key、PIN 校验值。iOS 用钥匙串（解锁后可访问、仅本设备）；Android 用 Keystore 保护的加密存储。读取不要求每次生物识别，否则无法同步。

### 6.3 输入保护

- 助记词：使用应用内的 BIP39 词表键盘（输入字母后点选候选词），不经过系统输入法。也支持整段粘贴，粘贴后提示用户清空剪贴板。
- 私钥、主密码：iOS 上使用系统安全输入框，第三方键盘被自动禁用；Android 上设置"不学习、不联想、密码类型"标志，并提示用户使用系统自带输入法。
- 所有敏感输入框关闭自动更正、联想和听写。

### 6.4 显示保护（`ScreenGuard`）

- Android：敏感页面设置禁止截屏标志，同时使任务切换器预览为空白。
- iOS：监听录屏与投屏状态，激活时隐藏明文并提示；切后台时覆盖遮挡视图；收到截屏通知后弹出警示。
- 明文默认遮挡，显示 60 秒后自动隐藏；页面不可见时立即清除。
- 不提供复制到剪贴板（PRD Q3 待定）。

### 6.5 内存处理

- 密钥材料尽量以字节数组持有，用完立即覆写清零。
- 解密、派生等操作在独立的 isolate 中进行，结束即销毁该 isolate。
- **已知局限**：Dart 字符串不可变且由垃圾回收管理，显示助记词时必然会产生无法主动清除的字符串副本。应对：缩短明文的存活时间，页面销毁后不保留引用；不把明文放进任何状态管理对象、路由参数或缓存。
- 明文不得作为参数传给日志、错误信息、异常对象。

### 6.6 设备完整性

启动时检测越狱或 root 的常见迹象。检测到时警告用户，不阻止使用（检测本身不可靠，仅作提醒）。

## 7. 应用锁（PIN）

- PIN 是**访问闸门**，不是保险库的加密依据。6 位数字的熵不足以抵抗离线暴力破解，因此保险库的安全性完全由主密码和硬件密钥承担。
- PIN 的 Argon2id 校验值存在系统安全存储中；错误次数与锁定截止时间同样存于此，防止通过重装或改时间绕过（锁定时间以单调时钟与系统时间两者中较保守者为准）。
- 应用锁定时：关闭数据库连接、清空内存中的资产数据、路由重定向到解锁页。
- 应用锁的生物识别只用于"代替输入 PIN"，与保险库的硬件包裹相互独立。

## 8. 安全自查清单（M4、M6 必须逐项通过）

**静态检查（CI 自动）**
- [ ] `ow_vault` 的依赖只包含白名单内的包；全包范围内没有任何网络相关的导入。
- [ ] 全仓库没有交易所的下单、划转、提现接口路径。
- [ ] 没有把敏感类型传给日志函数（自定义静态检查规则）。
- [ ] 依赖锁文件已提交且与清单一致。

**真机验证（手工）**
- [ ] 抓包：保险库的创建、导入、查看、导出全程无网络请求。
- [ ] 导出应用沙盒：数据库无法直接打开；保险库文件中搜索不到助记词片段。
- [ ] 设备日志中搜索不到助记词、私钥、Secret。
- [ ] iOS：做一次系统备份并恢复到另一台设备，app 数据为空。
- [ ] Android：系统自动备份中不含 app 数据。
- [ ] 新增一枚指纹或面容后，硬件包裹失效并要求主密码。
- [ ] 关闭设备锁屏密码后，app 给出提示且硬件包裹不可用。
- [ ] Android 明文页截屏得到黑屏或被拒绝；任务切换器中无内容。
- [ ] iOS 开始录屏后明文被隐藏。
- [ ] 主密码错误 5 次后被锁定；杀掉进程重启后锁定仍在。
- [ ] 卸载重装后旧数据不可恢复（iOS 上需确认钥匙串残留条目在首次启动时被清理）。
- [ ] 备份文件用独立工具在断网电脑上解密成功。
- [ ] 篡改备份文件任意一个字节后解密失败，且不输出任何内容。

## 9. 供应链

- 所有依赖锁定到确切版本，锁文件入库。
- `ow_vault` 的依赖白名单：`ow_domain`、派生库 `blockchain_utils`（ADR_004）、libsodium 的 Dart 绑定（接入时加入）、Dart 标准库。白名单写在 `tools/ci/check_deps.dart` 中，新增依赖需要写 ADR。
- `ow_vault` 自身代码不得导入 `dart:io`：文件读写通过注入的存储接口完成，由 `ow_data` 或 `ow_platform` 提供实现。
- 升级任何依赖前阅读其变更说明；升级 `ow_vault` 的依赖时还要审阅代码差异。
- 不使用带统计、广告、远程配置功能的 SDK。
- 原生层（Swift、Kotlin）只使用系统自带的安全框架，不引入第三方原生库。

## 10. 对外发布前必须补做的事（v1.0 不涉及）

- 第三方安全审计（至少覆盖 `ow_vault`、`ow_platform` 和备份格式）。
- 可复现构建与发布签名校验，防止假 app。
- 漏洞报告渠道与响应流程。
- 各应用商店对加密钱包类应用的合规要求核查。
- 开源保险库相关代码。
