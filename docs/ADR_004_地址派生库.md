# ADR 004：地址派生库

状态：已决定（M0 技术验证一的结论）· 2026-11-10

## 背景

保险库需要从助记词派生 EVM、Bitcoin、Solana、Tron 的地址（BIP39、BIP32、SLIP-0010、BIP44/49/84/86 及各链地址编码）。派生错误会让用户误以为资产丢失，所以这是 M0 必须先验证的风险。

## 候选

| 候选 | 情况（2026-11-10 查询 pub.dev） | 结论 |
|---|---|---|
| `blockchain_utils` 7.1.0 | 纯 Dart；**零依赖**；支持全部六个平台；2026-07 仍在更新；一个库覆盖所需的全部标准与地址编码 | 选用 |
| `bip39` + `bip32` + `ed25519_hd_key` 等组合 | `bip39`、`bip32` 自 2021 年后未更新；需要 4 个以上的库拼装，各自带传递依赖 | 不选 |
| `web3dart` / `wallet` | 只覆盖 EVM；`web3dart` 依赖 `http`，不能进入保险库 | 不选 |
| Trust Wallet Core 经 FFI | 成熟且经过审计；但需要为每个平台构建和分发原生库，桌面端成本高 | 备选：若日后对纯 Dart 实现失去信心再切换 |

## 验证

1. **官方向量**：BIP39 规范的种子向量；BIP84、BIP86 文档中的首个地址。
2. **独立实现对照**：用 Python 的 `bip_utils` 2.x（与所选库无代码关系）对三组公开测试助记词、9 种派生方案、每种前 5 个序号生成地址，共 135 个；Dart 实现的结果逐一相同。样本与生成脚本在 `packages/ow_vault/test/fixtures/`。
3. **联网检查**：库的源码不导入 `dart:io`、`dart:html` 或任何网络包；`tools/ci/check_deps.dart` 在每次 CI 中重复这项检查。

以上测试在 CI 中常驻。

## 决定

- `ow_vault` 使用 `blockchain_utils`，版本锁定为确切的 7.1.0。
- 只使用它的 BIP39 校验、种子生成、分层派生和地址编码。**不使用**它的签名、加密、钱包文件等功能；保险库的加密仍由 libsodium 承担（ADR_003）。
- 派生方案的路径模板定义在 `ow_domain` 的 `DerivationScheme`，库只接收路径字符串，方便日后替换实现。

## 后果与残余风险

- 该库由单一维护者维护，未见公开的第三方审计。它在本项目中只参与"算地址"，算错的后果是地址对不上（可被对照测试和真实钱包核对发现），不会直接泄露密钥；但它运行时会接触种子，因此升级版本前必须审阅代码差异（SECURITY_DESIGN 第 9 节）。
- 纯 Dart 的椭圆曲线运算不是常量时间实现。派生在本机离线进行，不暴露给远程计时攻击者，此风险可接受。
- 仍需补做：用真实钱包（MetaMask、Phantom、TronLink 等）导出的地址与本实现对照。这要等测试用小额钱包准备好后，在 M4 之前完成。
