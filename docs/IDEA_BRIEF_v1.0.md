# OneWallet 想法简报

> 版本 v1.0 · 2026-11-10 · 状态：待确认

## 一句话

给自己用的手机 app：在一处看到名下所有链上钱包和交易所账户的资产，并把所有助记词、私钥安全地存进一个离线加密保险库，避免因忘记备份或钱包停运而丢失资产。

## 目标用户与核心场景

**目标用户**：同时使用多个链上钱包和多家交易所的个人持币者。第一版只服务作者本人。

**核心场景**

1. **我现在一共有多少钱，分别在哪**：打开 app，看到总资产、按账户和按币种的分布。
2. **我的钱包都备份了吗**：查看备份清单，哪些钱包的助记词已入保险库、哪些还没备份、哪些是无助记词（MPC）钱包需要尽快处理。
3. **某个钱包 app 用不了了，我要找回助记词**：通过生物识别或主密码打开保险库，查看助记词，导入到别的钱包恢复资产。
4. **换手机或手机丢了**：用之前导出的加密备份文件和主密码，在新手机上恢复全部数据。

## 核心循环

打开 app → 解锁 → 自动同步 → 看总资产和变化 → 发现异常或未备份项 → 处理（补充地址、入库助记词、导出备份）→ 下次再来看。

回访动机：资产每天在变；备份清单上的红点没清完。

## 差异与价值

| 现有产品 | 不足 | OneWallet |
|---|---|---|
| DeBank、Zerion | 交易所覆盖弱；地址数据上传到对方服务器 | 链上和交易所一起看 |
| CoinStats、Delta | 闭源、API Key 存云端 | 本地优先，无自有后端，密钥不离开设备 |
| Rotki | 桌面端、偏记账报税 | 手机端，偏日常查看 |
| Rabby、OneKey 等钱包 | 不管交易所；没有"备份是否齐全"的视角 | 备份清单 + 保险库，专门解决"丢备份" |

## 第一版范围

- 链上钱包观察：EVM 系（Ethereum、BNB Chain、Arbitrum、Optimism、Base、Polygon）、Bitcoin、Solana、Tron。
- 交易所只读聚合：Binance、OKX、Bybit、Bitget。
- 总览、账户、资产详情、地址簿、净值曲线（本地快照）。
- 备份清单。
- 离线加密保险库：助记词和私钥的存、看、派生地址。
- 加密备份文件的导出和恢复，备份格式公开，附独立解密工具。
- iOS 和 Android，简体中文。
- 架构按多端设计：第一版只发布手机端，但核心逻辑与平台无关，后续可扩展到 macOS、Windows、Linux 桌面端和平板，不需要重写。

## 明确不做

- 不做签名、转账、交易、DApp 连接。
- 不做自有后端、账号体系、云同步。
- 不做会员和付费。
- 不做交易流水、盈亏分析、报税导出（列为后续候选）。
- 不做 DeFi 仓位深度解析（第一版只显示钱包内的币种余额）。
- 不做 NFT。

## 风险与验证方式

| 风险 | 验证方式 | 时点 |
|---|---|---|
| 助记词派生地址算错，用户误以为资产丢失 | 用各链官方测试向量和主流钱包实际地址做对照测试 | M0 技术验证 |
| 硬件密钥加生物识别在两个平台上的行为差异（指纹变更、换机、系统备份） | 写最小原生插件，在真机上逐项验证 | M0 技术验证 |
| Argon2id 在低端手机上太慢或内存不足 | 真机测速后定参数 | M0 技术验证 |
| 无后端时，链上数据 API 的免费额度和限频不够用 | M1 用真实地址跑一周 | M1 |
| 交易所各子账户余额接口不一致，总额对不上 | 与交易所 app 显示的总资产逐家核对 | M2 |
| 自己写的保险库有安全缺陷 | 威胁模型逐条自查；保险库模块不联网并由 CI 强制；长期保留纸质备份 | M4、M6 |

## 未决问题

1. 你日常主力机是 iPhone 还是 Android？（决定先在哪个平台做真机验证。）
2. 技术栈建议用 Flutter（见 ADR_001），是否同意？
3. 链和交易所的首批清单是否需要增减？
4. 视觉风格三选一（见 PROTOTYPE 文档第 2 节）。
5. 链上数据服务需要你自己申请免费 API Key（Alchemy、TronGrid 等），是否接受？
